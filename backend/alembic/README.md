# Database migrations

The phase-one schema is delivered through four ordered migrations:

1. 0001 — base tenant, academic, user, membership, RBAC and append-only audit tables.
2. 0002 — strict RoleBinding scope checks and composite tenant/school foreign keys.
3. 0003 — Telegram Account and one-time admin pairing; removes browser sessions and makes email/password optional metadata.
4. 0004 — durable processed Telegram Update leases for replay suppression.

Apply migrations after provisioning PostgreSQL:

    PYTHONPATH=backend alembic -c backend/alembic.ini upgrade head

## First platform owner

After migrations, provision the first owner using a numeric Telegram User ID that has been independently verified:

    PYTHONPATH=backend python -m app.cli create-platform-owner

The CLI creates the platform User, Telegram Account, platform_owner Role/Binding, required platform permissions and an audit event. There is no browser password or default credential.

## Administrator invitations

A permitted Platform Owner can create a one-time pairing invitation from the bot using:

    /invite TELEGRAM_ID Display Name

The generated deep link is restricted to that numeric Telegram ID, has a short expiry and is stored only as a hash. The raw token is returned once. The invited account receives no extra scope or role beyond the invitation's current bootstrap behavior; role assignment is a separate controlled capability planned for phase 2.

Never run autogenerated migrations against production without reviewing schema and data impact. Audit immutability is enforced by a PostgreSQL trigger and SQLAlchemy ORM events.
