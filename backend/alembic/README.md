# Database migrations

The initial phase-one migration creates the tenant, identity, session, scoped RBAC,
academic structure, and append-only audit tables.

Apply migrations after provisioning PostgreSQL:

    alembic -c backend/alembic.ini upgrade head

## Current bootstrap limitation

The CLI command below is present in the current PR branch but still provisions a browser-style
email/password owner. It is **not** the final Telegram-first administrator bootstrap and must
not be treated as the production owner-provisioning workflow:

    PYTHONPATH=backend python -m app.cli create-platform-owner

The final bootstrap must bind the first Platform Owner to a verified numeric Telegram User ID.
Additional administrators must be added through audited, one-time, expiring pairing tokens.
Never place a real bot token or administrator secret in source control, command-line arguments,
logs, or migration files.

Never run autogenerated migrations against production without reviewing schema and data impact.
Audit immutability is enforced in PostgreSQL by a database trigger and in SQLAlchemy ORM
by model events. Any future privileged maintenance procedure must preserve the audit trail.
