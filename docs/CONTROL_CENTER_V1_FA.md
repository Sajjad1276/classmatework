# کنترل‌سنتر ClassMate — اتصال گروه کلاس و گزارش رویدادمحور

## محدوده این برش

این نسخه پایهٔ عملیاتی دو قابلیت را می‌سازد: اتصال امن هر ClassGroup به گروه Telegram و نگهداری دادهٔ واقعی برای گزارش‌های مدیریتی. این برش، کل کنترل‌سنتر یا مدیریت همه قابلیت‌های ربات اصلی را تکمیل نمی‌کند.

## اتصال گروه به کلاس

### قواعد داده

- هر ClassGroup حداکثر یک رکورد ClassTelegramGroup دارد.
- شناسه Telegram Chat در کل سامانه یکتا است.
- کلاس و Tenant در دیتابیس با Foreign Key مرکب به هم متصل‌اند.
- گروه‌های مجاز فقط `group` و `supergroup` هستند.
- وضعیت اتصال: `active`، `revoked` یا `attention`.

### جریان اتصال

1. مدیر وارد صفحه جزئیات کلاس و سپس «مدیریت گروه تلگرام» می‌شود.
2. ClassMate Work کد تصادفی با عمر ۱۰ دقیقه صادر می‌کند. فقط SHA-256 کد در دیتابیس ذخیره می‌شود.
3. صدور کد تازه، کدهای مصرف‌نشده قبلی همان کلاس را لغو می‌کند؛ برای هر کلاس حداکثر یک کد فعال باقی می‌ماند.
4. مدیر ربات اصلی را به گروه اضافه می‌کند و دسترسی لازم را می‌دهد.
5. همان مدیر که کد را صادر کرده، دستور `/classmate_connect CODE` را در گروه ارسال می‌کند.
6. ربات اصلی باید با Telegram Bot API بررسی کند فرستنده مدیر گروه است و خود ربات نیز مدیر گروه است.
7. فقط پس از این بررسی، ربات اصلی Use Case مشترک `complete_class_group_handshake` را مستقیماً با Session بک‌اند اجرا می‌کند.
8. Use Case زمان اعتبار، Hash کد، شناسه مدیر صادرکننده، نوع گروه و یکتایی گروه/کلاس را بررسی و اتصال را در یک تراکنش ثبت می‌کند.

### فراخوانی مستقیم در بک‌اند مشترک

پس از بررسی واقعی Telegram Bot API، ربات اصلی تابع Application زیر را مستقیماً فراخوانی می‌کند؛ هیچ Route یا HTTP Service واسطی لازم نیست:

```python
connection = await complete_class_group_handshake(
    db,
    token=code,
    telegram_chat_id=chat.id,
    chat_title=chat.title or "گروه کلاس",
    chat_username=chat.username,
    chat_type=chat.type,
    actor_telegram_user_id=message.from_user.id,
    integration_bot_id=bot.id,
    bot_is_admin=True,  # فقط بعد از بررسی get_chat_member و تأیید مدیر
)
```

مقدار `bot_is_admin` فقط بعد از تأیید واقعی Telegram Bot API ارسال می‌شود. Use Case اعتبار، مصرف یک‌باره، تطبیق مدیر صادرکننده و یکتایی گروه/کلاس را در یک تراکنش کنترل می‌کند.

## گزارش‌های واقعی

### جدول‌های اصلی

- `usage_events`: رویدادهای یکتای مصرف؛ با External Event ID برای Idempotency.
- `usage_identities`: یک رکورد حداقلی برای هر شناسه ناشناس‌شده؛ وضعیت حساب و زمان اولین/آخرین مشاهده را نگه می‌دارد.
- `audit_events`: گزارش ممیزی عملیات مدیریتی؛ از Telemetry مصرف جدا می‌ماند.

### حریم خصوصی

- ربات مجاز در همان بک‌اند، پیش از ثبت رویداد تابع `build_usage_actor_hash(telegram_user_id, hash_key)` را اجرا می‌کند؛ فقط `actor_key_hash` وارد جدول‌های Telemetry می‌شود.
- شناسه خام در جدول UsageEvent یا UsageIdentity ذخیره نمی‌شود.
- `CLASSMATE_TELEMETRY_HASH_KEY` باید یک Secret پایدار باشد؛ تغییر آن هویت‌های آماری قبلی را دوپاره می‌کند. دیگر Integration Token یا fallback مبتنی بر آن وجود ندارد.
- فقط کلیدهای غیرمحتوایی مجاز در Attributes ذخیره می‌شوند: `feature`، `action`، `result`، `duration_ms`، `class_code`، `subject_code` و `source_screen`.
- متن پیام، فایل، محتوای درسی، رمز، Token و اطلاعات شخصی نباید وارد Telemetry شوند.

### رویدادها و وضعیت کاربر

- رویدادهای عادی مانند `class.opened` یا `lesson.viewed` اولین مشاهده را ایجاد می‌کنند و زمان آخرین مشاهده را به‌روز می‌کنند.
- `user.registered`، `user.activated` و `user.reactivated` وضعیت را فعال می‌کنند.
- `user.deactivated` وضعیت را غیرفعال و `user.blocked` وضعیت را مسدود می‌کند.
- Event ID تکراری دوباره پردازش نمی‌شود.

### تعریف شاخص‌ها

- کل کاربران: تعداد UsageIdentityهایی که در Telemetry شناخته شده‌اند.
- کاربران فعال حساب: UsageIdentityهایی با status فعال.
- کاربران جدید روز/هفته/ماه: first_seen_at در ۱/۷/۳۰ روز گذشته.
- کاربران فعال یک/چهار/دوازده ساعت: تعداد actor_key_hash یکتای دارای حداقل یک رویداد در هر بازه.
- مدارس/کلاس‌ها/درس‌ها: شمارش داده‌های واقعی جداول آموزشی.
- گروه‌های متصل: شمارش ClassTelegramGroup با status فعال.

آمار تاریخی قبل از اتصال Telemetry خودبه‌خود قابل بازیابی نیست. برای شمار کامل کاربران موجود، ربات اصلی باید یک Backfill کنترل‌شده از رویداد `user.registered` برای حساب‌های قبلی انجام دهد. بدون آن، گزارش «کل کاربران» فقط کاربرانی را می‌شمارد که از شروع Telemetry مشاهده شده‌اند.

## ثبت داخلی رویدادهای مصرف

ربات اصلی بعد از رخداد معتبر، تابع Application `ingest_usage_event` را مستقیماً فراخوانی می‌کند. شناسه ناشناس با `build_usage_actor_hash` و Secret سمت سرور ساخته می‌شود. Event ID برای Idempotency حفظ می‌شود و Attributes همچنان فقط از Allowlist می‌گذرند. هیچ Payload HTTP، Header مشترک یا سرویس واسطی وجود ندارد.

نمونه محاسبه شناسه:

```python
actor_key_hash = build_usage_actor_hash(
    telegram_user_id=message.from_user.id,
    hash_key=settings.classmate_telemetry_hash_key.get_secret_value(),
)
```

## مدیریت درس‌های هر کلاس

- فهرست درس‌های فعال مدرسه در صفحهٔ «مدیریت درس‌های کلاس» دیده می‌شود.
- مدیر دارای مجوز می‌تواند درس را به کلاس تخصیص دهد یا با تأیید از آن کلاس بردارد؛ خود رکورد درس حذف نمی‌شود.
- جدول `class_subjects` تاریخچهٔ تخصیص را با وضعیت فعال/غیرفعال نگه می‌دارد.
- دو Foreign Key مرکب اجازه نمی‌دهند یک درس از مدرسه یا مجموعهٔ دیگر به کلاس تخصیص داده شود.
- مجوز `class:subjects:manage` به مدیر مدرسه داده می‌شود؛ دسترسی خواندن فهرست جدا از مجوز تغییر است.

## ویرایش و بایگانی ساختار آموزشی

- مدرسه: ویرایش نام؛ کد سیستمی ثابت و غیرقابل‌ویرایش است. بایگانی فقط وقتی مجاز است که هیچ سال تحصیلی، کلاس یا درس فعال نداشته باشد.
- سال تحصیلی: ویرایش نام و بازهٔ تاریخ، با کنترل تداخل بازه‌ها در همان مدرسه. بایگانی فقط وقتی مجاز است که کلاس فعالی نداشته باشد.
- کلاس: ویرایش نام و پایه/مقطع؛ کد سیستمی ثابت است. بایگانی، اتصال گروه را لغو، کدهای اتصال مصرف‌نشده را باطل و تخصیص‌های درس را غیرفعال می‌کند.
- درس: ویرایش نام؛ کد ثابت است. بایگانی، تخصیص‌های فعال آن درس به کلاس‌ها را غیرفعال می‌کند.
- تمام عملیات از مجوزهای مستقل `school:manage`، `academic_year:manage`، `class:manage` و `subject:manage` عبور می‌کنند و Audit دارند.
- بایگانی نرم است؛ هیچ رکوردی به‌صورت فیزیکی حذف نمی‌شود. صندوق بایگانی و بازیابی از Bot انجام می‌شود: ابتدا مدرسه، سپس سال و در نهایت کلاس/درس.
- مدرسه با وضعیت `setup`، سال با وضعیت `planned` و کلاس/درس با وضعیت `active` بازیابی می‌شوند. فرزندان به‌طور خودکار همراه والد فعال نمی‌شوند.
- تخصیص‌های دستی حذف‌شده با وضعیت `inactive` از بازیابی مستثنا هستند. تخصیص‌های ناشی از بایگانی در وضعیت `suspended` نگهداری می‌شوند و وقتی هر دو طرف فعال شدند دوباره فعال می‌شوند.
- اتصال گروه تلگرام بعد از بازیابی کلاس همچنان لغوشده است و باید با Handshake جدید متصل شود.

## مرز استقرار

تنها سرویس اجرایی این مخزن ربات تلگرام است؛ PostgreSQL و Redis منابع مشترک Bot باقی می‌مانند. مسیر FastAPI، Endpointهای HTTP، وابستگی‌های Uvicorn/FastAPI و Secret اختصاصی M2M از این مخزن حذف شده‌اند. منطق Application برای فراخوانی مستقیم از بک‌اند مشترک حفظ شده است. هیچ تغییر یا Deploy روی `classmate2`، `classmate-worker` یا ربات اصلی انجام نشده است.
