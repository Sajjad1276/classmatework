# دفتر تصمیم‌های فاز صفر ClassMate Work

**وضعیت:** تصمیم‌های موقت و موارد نیازمند تصویب  
**قاعده:** وجود یک گزینه در این دفتر به معنی تصویب نهایی آن نیست.

## فرض‌های موقت برای ساخت زیرساخت

| موضوع | مبنای موقت | پیامد |
| --- | --- | --- |
| جداسازی پروژه | ClassMate Work مستقل از classmate2 است | هیچ کد یا تنظیمی در classmate2 تغییر نمی‌کند |
| معماری | Modular Monolith | ماژول‌ها مرز مشخص دارند؛ فعلاً microservice ساخته نمی‌شود |
| چندمستاجری | طراحی از ابتدا tenant-aware می‌شود | tenant_id در داده‌های tenant-owned و قراردادها لحاظ خواهد شد |
| backend | Python 3.12 و FastAPI | این انتخاب مطابق سند طراحی مرجع است |
| persistence | PostgreSQL و SQLAlchemy 2 | مدل‌های دامنه پس از تثبیت مالکیت داده ساخته می‌شوند |
| cache/queue foundation | Redis | در فاز صفر فقط اتصال و health check؛ صف عملیاتی هنوز وجود ندارد |
| web UI | React + TypeScript | پوسته‌ی فارسی و RTL؛ هنوز پنل احراز هویت‌شده نیست |
| زبان رابط | فارسی | کدگذاری و ساختار باید مانع افزودن زبان دوم نشود |

## تصمیم‌های باز

1. مدل تجاری: SaaS چندمستاجری عمومی یا نصب برای یک مجموعه‌ی مشخص؟
2. اولین persona عملیاتی: مدیر مدرسه یا مدیر کل پلتفرم؟
3. روش ورود: رمز عبور، OTP، ارائه‌دهنده‌ی هویت بیرونی یا ترکیبی؟
4. دامنه‌ی والدین: صرفاً classmate2 یا بخشی از پنل مدیریتی؟
5. عملیات مشمول تأیید دوم و اصل چهارچشمی.
6. دوره‌ی نگهداری، آرشیو، حذف و legal hold.
7. سیاست اتصال Telegram: webhook، polling یا پشتیبانی هر دو.
8. سطح تازگی گزارش‌ها و SLAهای عملیاتی.
9. پرداخت، اشتراک، quota و صورت‌حساب.
10. دامنه‌ی ترجمه و زمان فعال‌سازی رابط انگلیسی.

## مرز مجاز توسعه تا زمان تصویب

**مجاز:** ساختار پروژه، health checks، logging پایه، request correlation، CI، migration framework،
design tokens، پوسته‌ی غیرفعال UI و مستندات API.

**غیرمجاز تا تعیین قرارداد:** حساب مدیر پیش‌فرض، login نمایشی، role یا permission فرضی،
داده‌ی نمونه‌ی مدرسه در محیط production، CRUD مدیریتی، impersonation، export عملیاتی،
اتصال واقعی Telegram، انتشار محتوا و sync با classmate2.

## معیار خروج از فاز صفر

- API با فرمان مستند اجرا شود.
- تست‌های پایه در CI اجرا شوند.
- PostgreSQL و Redis در readiness دیده شوند.
- migration framework آماده‌ی دریافت اولین مدل باشد.
- رابط وب بدون ادعای قابلیت‌های پیاده‌نشده اجرا شود.
- قرارداد tenant context صریحاً به هویت احراز‌شده وابسته باشد.
- secretها در مخزن وجود نداشته باشند.
