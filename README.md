# ClassMate Work

مخزن مستقل هستهٔ مدیریت ClassMate. رابط انسانی این سامانه فقط ربات اختصاصی تلگرام است؛ هیچ پنل وب مدیریتی در دامنهٔ محصول وجود ندارد.

## وضعیت مخزن

- فاز ۱ در `main` با Commit `5b392473019f83bf8a022840cfe733a0f3ed96f8` ادغام شده است.
- بازسازی مرحله‌ای کنترل‌سنتر در شاخهٔ `phase-2/control-center-core` انجام می‌شود.
- این شاخه اکنون اتصال گروه تلگرام به کلاس، فهرست صفحه‌بندی‌شدهٔ گروه‌های کلاس، تخصیص درس به کلاس، ویرایش و بایگانی نرم مدرسه/سال/کلاس/درس، داشبورد فهرستی و هستهٔ گزارش‌گیری رویدادمحور را پیاده می‌کند؛ کل کنترل‌سنتر هنوز کامل نیست.
- سرویس Railway فعلی `classmatework` ربات مدیریت را از `main` اجرا می‌کند. کد این شاخه تا پیش از عبور از CI و انتشار جداگانه، روی Production اعمال نشده است.
- برای اتصال به هر کلاس، دکمهٔ «مدیریت گروه تلگرام» از جزئیات همان کلاس در دسترس است؛ فهرست سراسری گروه‌های کلاس نیز از منوی مدرسه باز می‌شود.
- در جزئیات هر کلاس، «مدیریت درس‌های کلاس» فهرست درس‌های فعال همان مدرسه را نشان می‌دهد و تخصیص/برداشتن درس را با مجوز انجام می‌دهد. شناسهٔ کلاس و درس در Callback به‌صورت مستقل حمل می‌شود و به وضعیت FSM وابسته نیست.
- بایگانی فیزیکی انجام نمی‌شود؛ وضعیت archived ثبت و Audit حفظ می‌شود. مدرسه تا زمانی که سال/کلاس/درس فعال داشته باشد و سال تا زمانی که کلاس فعال داشته باشد بایگانی نمی‌شوند.
- صندوق بایگانی و بازیابی مرحله‌ای مدرسه، سال تحصیلی، کلاس و درس از ربات مدیریت در دسترس است. بازیابی والد، فرزندان بایگانی‌شده را خودکار فعال نمی‌کند.
- بایگانی کلاس اتصال گروه را لغو و تخصیص‌های فعال درس را به وضعیت `suspended` می‌برد؛ بایگانی درس نیز همین کار را برای تخصیص‌های فعالش انجام می‌دهد. تخصیص دستی `inactive` باقی می‌ماند و خودکار بازنمی‌گردد.
- پس از بازیابی کلاس، تخصیص فقط وقتی فعال می‌شود که درس نیز دقیقاً فعال باشد. گروه تلگرام پس از بازیابی کلاس باید با Handshake جدید متصل شود.
- هیچ تغییری در مخزن یا سرویس `classmate2` و `classmate-worker` در این کار انجام نمی‌شود.

نقشه کلان دقیقاً پنج فاز در `docs/MASTER_ROADMAP_5_PHASES_FA.md` حفظ شده است.

## برش اول بازسازی کنترل‌سنتر

### اتصال گروه تلگرام به کلاس

- هر کلاس حداکثر یک رکورد اتصال دارد و هر شناسه گروه تلگرام فقط به یک کلاس اختصاص می‌یابد.
- اتصال با کد تصادفی یک‌بارمصرف، ۱۰ دقیقه‌ای و Hash-only آغاز می‌شود.
- کد به کاربر مدیری که آن را صادر کرده مقید است.
- گروه فقط از نوع `group` یا `supergroup` پذیرفته می‌شود.
- ربات اصلی باید پیش از تکمیل اتصال، مدیر بودن فرستنده و دسترسی مدیریتی خودش در گروه را با Telegram Bot API بررسی کند.
- قطع اتصال در ClassMate Work فقط رابطهٔ کلاس/گروه را غیرفعال می‌کند؛ ربات را از گروه حذف نمی‌کند.
- شناسه Tenant و Class با Composite Foreign Key به هم مقیدند تا اتصال بین دو مجموعه اشتباهاً ساخته نشود.

### گزارش و Telemetry

- شمار کاربران شناخته‌شده و وضعیت حساب از جدول `usage_identities` محاسبه می‌شود.
- تعداد کاربران فعال در بازه‌های یک، چهار و دوازده ساعت از اثرانگشت کاربران یکتای دیده‌شده در `usage_events` محاسبه می‌شود.
- کاربران جدید از زمان اولین مشاهده در Telemetry در بازه‌های یک، هفت و سی روز محاسبه می‌شوند.
- شناسه خام تلگرام برای آمار نگهداری نمی‌شود؛ Application Layer با `CLASSMATE_TELEMETRY_HASH_KEY` اثرانگشت HMAC می‌سازد و فقط Hash ذخیره می‌شود.
- برای نمایش شمار تاریخی همه کاربران، ربات اصلی باید هنگام یکپارچه‌سازی برای کاربران موجود رویداد `user.registered` را Backfill کند. بدون این Backfill، آمار از زمان شروع اتصال به بعد کامل خواهد بود.
- وضعیت حساب فقط با رویدادهای `user.registered`، `user.activated`، `user.reactivated`، `user.deactivated` و `user.blocked` تغییر می‌کند.
- Ping، CPU و Load سرور فعلاً نمایش داده نمی‌شوند؛ تا زمانی که منبع اندازه‌گیری معتبر وجود نداشته باشد عدد ساختگی ارائه نمی‌شود.

### اتصال به بک‌اند مشترک

- ربات مدیریتی و اجزای مجاز ClassMate از Application Layer مشترک استفاده می‌کنند؛ برای این ارتباط، سرویس HTTP یا FastAPI جداگانه اجرا نمی‌شود.
- پس از بررسی واقعی دسترسی مدیر و مدیر بودن ربات در Telegram Bot API، کد اتصال گروه با فراخوانی مستقیم Use Case `complete_class_group_handshake` مصرف می‌شود.
- رویدادهای مصرف نیز از طریق Use Case داخلی `ingest_usage_event` ثبت می‌شوند؛ تابع `build_usage_actor_hash` شناسه عددی تلگرام را با کلید محرمانه پایدار HMAC می‌کند.
- دسترسی مستقیم به جدول‌ها از Handlerهای تلگرام مجاز نیست؛ فراخوانی باید از Application Use Case عبور کند تا مجوز، اعتبارسنجی، تراکنش و Audit حفظ شود.
- در این مخزن هیچ FastAPI Service، Endpoint HTTP یا Secret مشترک M2M نگهداری نمی‌شود. آداپتر غیرضروری HTTP حذف شده است؛ مدل‌ها و منطق دامنه حفظ شده‌اند.

## اجرای محلی

نیازمندی‌ها: Python 3.12+ و Docker Compose.

1. فایل `.env.example` را به `.env` کپی کنید.
2. PostgreSQL و Redis را اجرا کنید.
3. Migrationها را با `PYTHONPATH=backend alembic -c backend/alembic.ini upgrade head` اعمال کنید.
4. مالک اولیه را با `PYTHONPATH=backend python -m app.cli create-platform-owner` بسازید.
5. برای Bot مقدار `TELEGRAM_BOT_TOKEN` را فقط در Secret محلی قرار دهید.

سرویس HTTP وجود ندارد. Bot با `PYTHONPATH=backend python -m app.bot.main` یا `docker compose --profile bot up admin-bot` اجرا می‌شود. Token واقعی نباید در Git، Audit یا Log قرار گیرد.
